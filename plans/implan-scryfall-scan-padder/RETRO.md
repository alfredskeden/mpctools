# Retro

## 2026-09-07: Scryfall Scan Padder — /padder + /padder-scrub, end to end

| Category | Details |
|---|---|
| **Went well** | • The "layout is a pure function, not state" decision held all the way through: `computePadLayout` is DOM-free, so every pad-math item in `TEST_STRATEGY.md` (1–12) is a plain unit test and the hook stayed thin (image, file name, target, downloaded flag).<br>• The suggested order of work (math → renderer → prompts → hook → components → pages → entry points) ran without backtracking; each layer's tests were already green before the layer above it existed.<br>• Reusing `BG_COLOR` and `downloadCanvasAsBlob` instead of `usePrepWorkflow`/`TransformCanvas` avoided dragging in scale state — the "no controls" property is now asserted by absence (item 23), so a future reintroduction fails the suite.<br>• Final state: 107 test files, 1368 tests, all passing; 100% coverage thresholds and `pnpm lint:ts` clean. |
| **Problems** | • The original pad design was wrong and had to be replaced mid-flight (commit `8e85dc3`): it padded every scan up to the nearest of four fixed MPC sizes (816x1110, 1632x2220, …). A 672x936 Scryfall "large" jpg is a ~268 DPI card, so it got 72/87px of grey instead of a bleed. Rewriting to the single bleed-reference ratio touched `lib/padder-math.ts`, its test file, and all four plan docs.<br>• The second route was built as `/padder-outpaint` and renamed to `/padder-scrub` after the fact (`6346d6f` file moves, `ff0e676` content), rippling into layout, page, sitemap, component names and four test files. Naming was not settled before code existed.<br>• `/padder-scrub` prompt copy shipped as placeholder-with-TODO first and was replaced with final supplied copy in `ff0e676`; `MENTAL_MODEL.md` still claims the prose "is not final", which is now stale. |
| **Learnings** | • Bleed is a ratio, not a size. Derive the canvas from the scan (`canvasW = max(round(imgW*816/745), round(imgH*816/1040), imgW)`), and the standard MPC print sizes fall out on their own when the scan sits at a standard DPI. Never make those sizes an input.<br>• Ratio labels must be declared per target, not gcd-reduced: `816x1110` reduces to `136:185`, which is useless in a Gemini prompt. `/outpaint`'s `buildHandshakePrompt` does reduce — do not copy it.<br>• 29:36 crops from the bottom only, keeping the image's original `x`/`y`; it cuts 62px of real card art on a 745x1040 scan. Confirmed intentional — report the number in the UI, never clamp or re-centre.<br>• Paste input (`hooks/use-paste-image.ts`) was added after the plan was written (`87061ee`) and folded back into `MAIN.md`/`NOTES.md`/`TEST_STRATEGY.md`, so a Scryfall image can skip the download-then-upload trip. Sharing the upload load path made it a small hook plus one wiring point. |
| **Risks** | • Verification items 34–36 in `TEST_STRATEGY.md` are the **manual** pass — a real Scryfall png padded at both targets, compared pixel-for-pixel, then fed to Gemini. Canvas mocks cannot judge "the grey looks right and nothing was resampled", and there is no record in the plan that this pass was run.<br>• The bleed ratio rests on one unvalidated reference pair (745x1040 → 816x1110). If that pair is off, every canvas at every resolution is off by the same proportion, and the unit tests would all still pass because they encode the same pair.<br>• `MENTAL_MODEL.md`'s placeholder-prompt paragraph contradicts shipped code; a future session reading it may re-do the copy work.<br>• `PADDER_TARGET_KEY` is written only on download. A user who navigates to `/padder-scrub` without downloading silently gets the 300 DPI default target's ratio in the prompt, which may not match the scan they are about to scrub. |
